# SearchRelay v0.1.0

**Released:** 2026-10-25 · **Tag:** `v0.1.0` · **License:** Apache-2.0

The first public release of SearchRelay: a self-hostable web search and fetch
layer for AI agents with a DeepSeek-compatible API.

!!! info "What this release is not"
    SearchRelay does not own a web index and does not claim to. It is the
    layer between your agent and the search corpus you choose to run —
    official provider APIs, a SearXNG instance you operate, or your own sites
    through the optional private index.

## Highlights

- **A stable, DeepSeek-compatible contract** for `POST /v1/tools/search` and
  `POST /v1/tools/fetch`: the same fields, the same error envelope, and the
  same billing semantics (a Search is billable only when it returns results).
- **Provider federation** across Brave Search API, Serper, Tavily, Exa,
  SearXNG, and the optional local index, merged with Reciprocal Rank Fusion,
  deduplicated by canonical URL, with timeouts, jittered retries, circuit
  breakers, budgets, and failover. `X-Providers-Used` shows who answered.
- **Operators enforced locally**, so an upstream that ignores `site:` or
  `-term` cannot leak results past the filter.
- **A two-tier cache** with TTLs by content type, `ETag`/`Last-Modified`
  revalidation, and request coalescing, plus `POST /v1/tools/search/batch`.
- **Safe fetching**: public-IP-only DNS resolution with pinning, redirect
  revalidation, `robots.txt`, and clean Markdown extraction from HTML and
  PDFs.
- **Transparent ranking**: `rerank_score` on a true 0–3 scale with a
  configurable YAML authority list.
- **Agent integration**: an MCP server, Python/TypeScript/Go SDKs, a LangChain
  tool, a LlamaIndex reader, and three runnable examples.
- **Operations**: Prometheus metrics, structured JSON logs, optional
  OpenTelemetry tracing, Redis-backed shared limits and billing, and an admin
  CLI.

## Upgrade notes

The environment prefix was renamed from `SF_` to `SR_` to match the project
name.

```diff
-SF_API_KEYS_JSON={"sk-example":"demo"}
-SF_INITIAL_BALANCES_JSON={"demo":100000000}
-SF_UPSTREAM_URL=http://searxng:8080
+SR_API_KEYS_JSON={"sk-example":"demo"}
+SR_INITIAL_BALANCES_JSON={"demo":100000000}
+SR_UPSTREAM_URL=http://searxng:8080
```

The old names still work as a fallback, so **no immediate action is
required**. When both prefixes define the same setting, `SR_` wins. The
service logs a deprecation warning listing the old variables it used.

Two other renames affect code, not deployment:

| Before | Now |
|---|---|
| `from searchfetch import SearchFetchClient` | `from searchrelay import SearchRelayClient` |
| `github.com/searchfetch/searchfetch-go` | `github.com/CocoCopi/searchrelay/clients/go` |

The user agent changed from `DeepSeekBot/1.0` to `SearchRelayBot/1.0`. If
you allowlisted the old agent in a `robots.txt` rule, update it.

## Known limitations

- The committed benchmark report is a **synthetic harness self-test**. It
  proves the harness and the metrics work over the 100-query golden set; it is
  **not** evidence about provider result quality. No live provider quality
  numbers are published yet.
- The Docker image is built by CI but is not published to a registry.
- The local index is SQLite FTS5 and suits small private corpora.
- The optional ONNX cross-encoder reranker ships no model and has not been
  benchmarked against the heuristic in this repository.
- Playwright rendering and OpenTelemetry tracing are experimental and off by
  default.
