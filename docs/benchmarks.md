## Method

- nDCG@10 uses exponential gains (`2^grade - 1`) and logarithmic discount.
- Relevance judgments are domain-level. The most specific judged domain wins.
- A failed logical query contributes nDCG 0 and is included in latency percentiles.
- Direct-provider rows measure adapter retrieval. The federated row measures RRF ordering after canonical-URL deduplication.
- Page fetching, reranking, billing, and HTTP API overhead are excluded.

## Limitations and honest status

- **This run is synthetic.** It proves the harness and metric implementation, but it is not evidence about Brave, Serper, Tavily, Exa, or SearXNG quality.
- A live provider run requires that provider's official API credential. Rows skipped for missing credentials are not failures and have no quality score.
- Live results vary with time, locale, upstream ranking changes, and provider coverage. Keep the generated JSON and this report with any release claim.
- The golden set contains domain-level judgments, not exhaustive URL-level ratings, so nDCG is a reproducible relative signal rather than an absolute measure of web quality.
- The benchmark does not measure end-to-end API latency, cached warm-cache latency, fetch latency, or the optional cross-encoder reranker.
